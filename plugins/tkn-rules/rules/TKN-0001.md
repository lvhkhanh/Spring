# TKN-0001 — Avoid optional `AS` in DB2 SQL

## Status

Active

## Scope

DB2 SQL authored or changed for this request, including embedded SQL and query strings. It does not apply to another SQL dialect, prose, comments, or identifiers that happen to contain `AS`.

## Rule

Do not add `AS` when DB2 accepts the statement without it. If an existing DB2 SQL fragment is being edited, remove an optional `AS` in the edited fragment unless doing so would reduce required compatibility or violate an explicit user requirement.

Use `AS` only when it is mandatory for the target DB2 syntax, required by a proven parser/tooling constraint, or explicitly requested by the user. Record the reason in a nearby comment or change note when using such an exception.

## Rationale

This convention keeps DB2 SQL concise and consistent while preserving syntax and compatibility as the deciding constraints.

## Examples

Compliant table alias:

```sql
SELECT e.EMPNO
FROM EMPLOYEE e
```

Non-compliant when `AS` is optional:

```sql
SELECT e.EMPNO
FROM EMPLOYEE AS e
```

Compliant column alias where the DB2 target permits the alias without `AS`:

```sql
SELECT e.LASTNAME employee_last_name
FROM EMPLOYEE e
```

## Verification

- Review DB2 SQL changed by the request for optional ` AS ` alias syntax.
- Run the repository's DB2-compatible SQL validation or tests when available.
- Do not perform a blind global replacement; preserve literals, comments, non-DB2 SQL, and required syntax.
